# The Liminal Terminal — Mobile Game Flow

How the mobile `/trade` experience works: the player taps into the on-screen
laptop and enters "The Liminal Terminal," a CRT hub fronting a token-forensics
calibration game. Preview the whole flow at **`/trade/comms-preview`**.

## Core idea

The game logic + data are presentation-agnostic — the cases, the four character
"lenses," the questions/evidence, the confidence-slider verdict, and the Brier
scoring all live in `src/components/game/cases/`. Only the *presentation* differs:

- **Desktop** (`CyborgTempleScene`): a 3D trading floor; consultants are talking
  heads via heavy SitePal mesh projection.
- **Mobile**: you don't walk among the consultants — you operate the terminal and
  **dial into them**. Everything is a transmission on the CRT. Much lighter, and a
  stronger fiction.

## Flow

tap laptop → **BOOT** → **HUB** → **CASE FILE** → **COUNCIL** → **CHANNEL** →
**VERDICT** → **REVEAL** → return.

| Step | Screen | Component |
|---|---|---|
| Boot / login | "Welcome to the Liminal Terminal" auth typing → reveals hub | `TerminalBoot.jsx` |
| Hub | `LIMINAL SCAN` (assessment) · `CASE FILES` · ▶ Intro Feed (video placeholder) | `TerminalBoot.jsx` (`HUB_OPTIONS`) |
| Case file | Case briefing + surface metrics + `BEGIN INVESTIGATION` | `TerminalMenu.jsx` |
| Council | 2×2 comms grid of the 4 lenses (CRT "standby" feeds) | `CommsGrid.jsx` |
| Channel | One consultant's live feed + questions (3 scans) + evidence cards | `ChannelView.jsx` + `SitePalFeed.jsx` |
| Verdict | One confidence dial — Trust ↔ Abstain ↔ Doubt | `VerdictScreen.jsx` |
| Reveal | Outcome (Aligned/Missed/Abstained) + Brier + each consultant's vindication + decisive lens | `RevealScreen.jsx` |

All orchestrated by `MobileTerminalGame.jsx` (the screen state machine), which
`TradeLaptop.jsx` mounts (portaled to body) when the laptop is tapped on mobile.

## Consultant feeds (live SitePal)

One consultant at a time, shown as a flat 2D feed — **not** the heavy desktop
per-frame mesh projection. Reuses SitePal account `9308752` + per-character
scenes (Monk `2774449` / Demon `2774900` / Detective `2774916`) + hash. Speaks via
`sayAudio(<case slot>)` if recorded, else live `sayText` in the station voice.
Eugene has no SitePal scene → text/portrait. **Confirmed performant on a real
device.**

The COUNCIL grid stays as still CRT portraits — SitePal is one-embed-per-page, and
four live avatars would be far too heavy; opening a channel "brings them live."

## The four-lens color system

The four lenses share one palette across the whole product
(`src/components/CaseFile/characterMeta.js` → `CHARACTER_META.color`): gold
(Monk · ETHOS), magenta (Demon · PATHOS), cyan (Detective · LOGOS), green
(Eugene · MYTHOS). It runs through the **desktop beacon's four strands → the
mobile SIGNAL knot → the comms-grid channels** as one visual system.

## Recording the consultant lines

All dialogue slots to record live in **[`docs/trade-rerecord-manifest.md`](./trade-rerecord-manifest.md)**
(auto-generated by `scripts/gen-rerecord-manifest.mjs`; **139 slots** across
cases 001–003, grouped by case → character, with each character's SitePal voice
config). Record them in the SitePal account; **slot names must match exactly**
(SitePal's 25-char cap means several are truncated, e.g. `case001_demon_react_belie`).
Source text lives in `src/components/game/cases/case-00N.js`.
